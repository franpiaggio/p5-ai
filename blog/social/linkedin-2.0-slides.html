Format 1 of 6

Full-file rewrite

function setup() { createCanvas(windowWidth, windowHeight); } function draw() { background(48, 24, 38); translate(width / 2, height / 2); // ...rest of the file, resent unchanged }
+
Nothing to locate. The edit cannot land in the wrong place
+
The only option for brand-new files
−
Output tokens for every unchanged line: ~2,400 tokens for a 1-line edit in a 300-line file
−
Models truncate long rewrites ("rest unchanged"), silently deleting what they skip

Format 2 of 6

Line-number edits

{ "start_line": 7, "end_line": 7, "replacement": " background(48, 24, 38);" }
+
Minimal tokens, trivial to parse
+
Fits tool-calling APIs naturally
−
Models read a token stream, not a numbered grid: "line 7" is often line 6 or 8, applied with full confidence
−
Applying edit 1 shifts the line numbers of edits 2 and 3 in the same reply

Format 3 of 6

Unified diff

@@ -4,7 +4,7 @@ function draw() { - background(30); + background(48, 24, 38); translate(width / 2, height / 2);
+
Compact, seen millions of times in training
+
Context lines anchor the change to content, not just position
+
Cut lazy-coding failures roughly in half vs full files (Aider)
−
Hunk headers are line numbers again, and models get them wrong
−
Only works when the applier ignores the numbers and searches for the context lines

Format 4 of 6

Search/replace blocks

<<<SEARCH background(30); === background(48, 24, 38); >>>REPLACE
+
Content-addressed: quoting text it just read is the model's core skill
+
~30 output tokens instead of ~2,400 for the same edit
+
Failures are fixable client-side with a matching cascade: exact → whitespace-insensitive → indentation-insensitive
−
Near match: a trailing space or a tab breaks exact matching
−
Fuzzy matches must be unique in the file, or the edit lands in the wrong spot

Format 5 of 6

Lazy edit + apply model

function draw() { background(48, 24, 38); // ... existing code ... }
+
The big model decides what to change; a small fine-tuned model works out where
+
Merges at ~1,000 tokens/s with speculative decoding (Cursor)
+
Laziness stops being a failure mode: it is the format
−
You train, host and serve a second model
−
Its merge mistakes are a new failure surface you own

Format 6 of 6

Structural (AST) edits

{ "replace_function": "draw", "body": "function draw() {\n background(48, 24, 38);\n ..." }
+
Function names are stable addresses: no off-by-one possible
+
A parser can verify the result compiles
−
Whole-unit granularity: a 1-line change resends the 60-line function
−
Imports, constants and CSS have no unit to address
−
One parser per language for the applier
